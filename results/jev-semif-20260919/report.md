### 具体差异

Jev 在下面题目的两轮均符合预设参考答案；SemIf 的差异可在原始记录复查。

- **policy04**：明确规则是“生产故障或重复扣款任一发生即紧急”。生产正常但重复扣款，参考是紧急；SemIf 两轮都选普通，所选概率 0.543 / 0.644。
- **reasoning04**：等待 2、4、8 秒的总和，参考 14 秒；SemIf 两轮选 16 秒，所选概率 0.789 / 0.620。实际应用应直接用代码算术。
- **reasoning08**：三人恰好一人拿钥匙，甲没拿，且“乙没拿则丙也没拿”，所以乙拿了；SemIf 第一轮选丙，第二轮正确。
- **reasoning06**：盒子重量顺序 D>A>C>B，参考 B 最轻；SemIf 第一轮正确，第二轮选 A。
- **reasoning07**：版本2把超时从5秒改成10秒，版本3只改颜色并继承其他设置；参考10秒，SemIf第二轮选5秒。加入无关档案后（reasoning07_long），两轮都选5秒。

这提示规则组合、状态更新与推理是当前 SemIf 的重点检查项；不能仅由这些题推断所有相关任务都会出错。

## 延迟

同一客户端，两家分别复用 HTTPS 连接；随机交错提供方先后顺序，两轮随机题目及选项顺序。一次请求一个 Choice。首请求和各3次预热排除，无重试、无请求错误。

| 输入组 | 每方样本 | Jev HTTP P50 / P95 | SemIf HTTP P50 / P95 |
|---|---:|---:|---:|
| 基础短题 | 96 | 143.4 / 277.0 ms | 119.6 / 263.0 ms |
| 长上下文 | 12 | 148.0 / 241.3 ms | 185.6 / 212.3 ms |

SemIf 实际输入：短题 122–159 tokens，长题 1609–1624 tokens。Jev 的内部模板和分词器不同，token 数不可直接等同。长组只有 12 次，P95 接近极值，应谨慎解释。

SemIf 的模型前向耗时 P50 / P95：短题 47.2 / 59.7 ms；长题 107.3 / 124.9 ms。Jev 不返回可直接对齐的服务器推理时间，因此主表只比较客户端到完整响应的 HTTP 耗时。这不是两家 GPU 硬件的比较。

两家服务位置、代理、负载与未知缓存均可能影响结果。本次交错测试减少时间顺序偏差，但不是长期 SLA 或完全隔离变量的实验。Jev 的多问题并行接口未参与本次单题比较。

## 实现与概率限制

- Jev 实际响应版本均为 `jev-1.13.0`。
- SemIf 源码 `b9cb32537e78be65f19abfcb1de8fc504b627d84`，模型 `Qwen/Qwen3.5-4B`，revision `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`，BF16，Torch 2.10.0+cu128，Transformers 5.17.0。
- H100 日志确认缺少 `causal_conv1d` 和 `flash-linear-attention`，使用参考 PyTorch 路径。因此测的是当前部署，不是优化后的最佳表现。
- 同一语义状态、问题和选项通过各自原生 API 封装。参考答案及理由不会被发送给模型。
- 首轮多分类 Brier：Jev 0.00174，SemIf 0.07487（越低越好）。小型题集不能证明泛化校准，也不能用来直接定生产置信度阈值。SemIf 返回的是未校准条件选项概率。
- 只测试 Choice；不代表自由生成、工具执行成功率、其他原语、批处理或高并发性能。
